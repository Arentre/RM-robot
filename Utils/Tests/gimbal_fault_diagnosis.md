# Pitch 突然前倾、随后云台失能：排查记录

本次已完成代码排查和保护补强，尚未在实机复现，不能确定硬件根因。

## 已确认的代码行为与缺口

- 底盘使用 CAN1，云台使用 CAN2。底盘正常不能排除 CAN2、云台供电或电机故障。
- Pitch 的主反馈来自 BMI088 的 IMU 姿态；编码器零点 240° 没有参与当前 IMU Pitch 绝对角控制。偶发少量电机反馈丢帧，不会直接把 Pitch 目标改成前倾。
- 原 IMU 姿态、角速度、加速度分三个队列更新，无采样时间戳；任务停更时，控制器可以无限使用仍为有限数的旧值。
- 原 BMI088 采集忽略 SPI/DMA 返回值，DMA 完成等待无超时。启动失败可能令姿态任务卡住。
- CAN2 的自动重传和自动 bus-off 恢复均关闭。HAL 发送成功仅表示入邮箱，不能证明线上发送成功，更不能证明两个电机收到命令。本次保留该总线配置，以故障记录定位原因。
- 原保护包含 CAN RX 超时 150 ms、发送入邮箱超时 100 ms、电流不跟随 300 ms、Pitch 超过 ±80°、过大角速度。任一轴异常会关闭整个云台，因此“先 Pitch 掉下，再双轴失能”可能是驱动先失去力矩，软件保护随后触发。
- CAN 任务在云台控制输出停更 50 ms 后归零。控制任务卡顿也可能先表现为 Pitch 失去支撑。
- 无导电滑环时，持续底盘自旋可能扭转跨轴线束。应记录故障是否与旋转方向或累计圈数有关，并检查 Pitch 电源和 CAN2 接头是否被拉扯。
- USB `STOP` / `ENABLE=0` / 视觉空闲命令会调用 `Gimbal_SerialStop`，并关闭全局 Pitch LADRC；`PITCH=0` 也会关闭 Pitch。若当时接着使用遥控控制，需要检查 `gimbal_ladrc_pit_enable`。这些是明确的控制指令路径，不能误判成 CAN 丢帧。
- USB `ENABLE=1` 曾按 Yaw 单轴测试流程强制关闭 Pitch。2026-11-12 已改为同时开启双轴；`PITCH=0` 才显式选择单轴。Pitch 启用状态已加入快照。

## 本次保护改动

- 新增整包 IMU 队列，同时携带陀螺仪与加速度计的采样时间；任一数据超过 20 ms 未更新，锁存停机。
- SPI/DMA 启动检查，DMA 完成等待最多 5 ms，失败后中止传输并释放片选；失败数据不刷新采样时间。
- 检查有限数及传感器量程；相邻 Pitch 变化允许 5° 解算修正加 1000°/s 实际运动，超过即在控制前停机。
- GM6020 编码器原始值必须小于 8192；非法帧计数并丢弃，不更新反馈时间戳。
- 输出发送前检查有限数及归一化范围 ±1；异常双轴输出归零，禁止异常浮点数转为整数电流指令。
- 新增 bus-off、遥控命令超时、控制输出停更诊断；记录最新一次保护触发前的快照。解除保护不会抹掉记录，断电或复位会丢失。
- 遥控保护锁存后，需先收到 `RELAX` 再恢复；串口需显式重新使能。保护条件持续存在时再次触发。原有遥控开关映射保持不变。
- 云台任务栈从 1024 B 增至 1536 B，给 Debug 调用链与浮点上下文留余量；未发现足以认定原故障是栈溢出的证据。

## 下次故障如何取证

复现后先不要复位，USB 串口发送 `FAULT` 加回车/换行，保存整行 `ack:FAULT,...`。也可在 Keil Watch 查看 `gimbal_fault_snapshot` 和 `gimbal_protection_status`。

| reason | 保护触发条件 | 排查方向 |
| --- | --- | --- |
| 0 | 尚无保护快照 | 排查主动 STOP/PITCH=0/ENABLE=1、复位、驱动失能等路径；此时快照其余零值不是现场数据 |
| 2 | 串口轨迹超过 250 ms 未更新 | 上位机轨迹发布是否停顿 |
| 4 | 角速度超过保护阈值 | 实际失控、IMU 数据异常，结合姿态和输出 |
| 5 | 非有限反馈或反馈超出数据范围 | IMU/SPI、内存或解算异常 |
| 6 | Pitch 超过 ±80° | 可能是失去力矩后的二次保护，不能单凭此项认定根因 |
| 8 | 目标或遥控增量非法 | 串口目标、命令构建与内存 |
| 9 | 长时间无法入发送邮箱 | CAN2 发送状态、邮箱与任务运行 |
| 10 | 已使能轴反馈电流连续超过 5 A 达 300 ms | 结合输出、反馈及持续时间定位；电流比例仍需实测核对 |
| 11 | 电机反馈超时 | `rx_ms` 先 Yaw 后 Pitch，检查断电、线束、终端电阻、CAN2 |
| 12 | IMU/加速度数据停更 | `imu_ms`、`acc_ms`、`imu_err`，区分传感器或采集停顿 |
| 13 | Pitch 反馈不合理跳变 | `prev_deg`、`pit_deg`、`gyro`，检查解算、SPI、内存 |
| 14 | 控制输出非法 | 控制器状态、参数或输出传递过程 |
| 15 | 遥控命令队列停更 | RC 任务与命令发布 |
| 16 | 控制输出停更超过 50 ms 后控制恢复 | 云台任务调度、执行耗时 |
| 17 | CAN2 bus-off | `esr` 与线束/接地/终端/电源检查 |

`out`、`current`、`temp`、`rx_ms`、`mismatch` 均按 Yaw/Pitch 顺序。`gyro` 为 rad/s，`pit_deg` 为角度，`out` 为归一化电流指令。`tx_ms` 是入邮箱成功的年龄。`esr` 是硬件 CAN ESR 快照，BOFF 位为 bit 2，TEC 为 bits 23:16，REC 为 bits 31:24。

`imu_err` 包括初始化、SPI/DMA、解算失败累计次数，不能单凭累计非零判定本次故障。`bad_rx` 是非法编码器帧累计数，CRC 正确且数值仍在范围内的错误数据无法仅靠此检查识别。

保护归零只能阻止继续施加异常力矩；Pitch 重心不平衡、供电或总线中断时，纯软件不能保证机构不因重力下落。

## 验证

Keil `Debug` 与 `DevC` 均已编译通过。`DevC` 保留 4 条原有的 `{0}` 零初始化风格警告，未出现编译错误。本次未烧录、未进行实机故障复现。

主机故障注入测试 `test_gimbal_fault_guard.c` 直接调用生产 CAN 解码与发送函数，覆盖错误总线、非法编码器、NaN/Inf/越界输出、时间戳回绕、长时间停更及 Pitch 跳变。`run_gimbal_fault_guard.ps1 -Compiler <tcc.exe 路径>` 在临时目录准备测试，stubs 不加入固件工程。

主机测试不覆盖真实 CAN 电气故障、SPI DMA 时序、电机驱动状态与机构运动；这些需要实机故障记录确认。
